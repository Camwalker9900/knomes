# packages/shared — API contract types & fixtures

This package is the neutral ground where the FastAPI backend and the Next.js
frontend agree on the wire format.

## What lives here

- `src/contracts.ts` — TypeScript declarations that mirror the backend's
  Pydantic response schemas 1:1 (`PropertySearchResult`, `PropertyDetail`,
  `TimelineEvent`, `FindingDetail`, `TransactionCycleOut`,
  `SourceProvenance`). JSON field names in `plan/CONTRACTS.md` are the frozen
  contract; these types must never drift from them.
- `fixtures/` — JSON payloads **generated by the backend** (serialized
  straight from the Pydantic response models with `model_dump(mode="json")`,
  using fixed UUIDs/dates so output is byte-for-byte deterministic). They are
  checked in so the frontend can test against real backend output without a
  running API. Files: `search.json`, `property_detail.json`, `timeline.json`,
  `findings.json`, `transactions.json`, `sources.json` — each in the exact
  envelope its endpoint returns (`{"results": [...]}` etc.).

## How the parity loop works

1. `apps/api/scripts/generate_contract_fixtures.py` builds representative
   in-memory response objects (no database) and writes the JSON files here:
   `cd apps/api && uv run python scripts/generate_contract_fixtures.py`.
2. `apps/api/tests/test_contract_fixtures.py` rebuilds the same objects via
   the script's builder functions and asserts byte equality with the committed
   files — any backend schema drift fails `pytest`.
3. `apps/web/src/lib/contracts.test.ts` imports the same files and checks them
   against the client types in `apps/web/src/lib/types.ts`: structurally at
   compile time (`satisfies`, enforced by `npm run typecheck` and the build)
   and enum values at runtime (`npm test -- --run`).
4. If either side changes shape, one of the suites fails — the contract cannot
   silently break.

To change the contract intentionally: update the Pydantic schemas and
`types.ts` together, rerun the generator, and commit the regenerated JSON.
Never edit the JSON by hand — the backend test asserts byte-for-byte equality
with the generator's output.
